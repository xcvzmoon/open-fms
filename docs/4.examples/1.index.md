## Before you start

You need a running Open FMS instance, an active caller API key with upload and file-read permissions, and a storage backend ID available to that caller. The examples use a local `report.pdf` file.

Set these values in the terminal that runs your client or backend:

```bash
export FMS_URL=http://localhost:3000
export FMS_API_KEY='<caller-api-key>'
export BACKEND_ID='<storage-backend-id>'
```

Keep the API key on your backend. Do not put it in browser code or public runtime configuration.

## Upload lifecycle

These examples use `proxy_single`: create a session, then send the bytes to its content URL. The PUT response means the upload was accepted for scanning. Read `GET /api/v1/files/{fileId}` and wait for `status` to become `clean` before requesting content. A failed or rejected scan does not make a file downloadable.

See the [API reference](/api) for other upload modes and the [scanning guide](/docs/scanning) for scan behavior.
