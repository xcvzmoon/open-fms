# Getting Started

Open FMS is a file management API for S3-compatible object storage. Other services call it over HTTP. They do not need an S3 SDK, bucket names, or storage credentials.

The core security rule is simple: **if PostgreSQL does not say a file is `clean`, those bytes are not downloadable.**

## What you get

- Upload through the API (single stream, resumable parts, or direct presigned PUT)
- Quarantine until malware scanning completes
- Promotion of clean objects only
- Downloads gated by database status
- Per-caller quotas, API keys, retention, and audit events

## Requirements

- Node.js 26
- pnpm 12.5.1 (managed by Vite+)
- PostgreSQL 16
- Optional: MinIO / RustFS / AWS S3, ClamAV, SMTP

## Install

```bash
cp .env.example .env
vp install
```

Minimum environment variables:

| Variable                                              | Purpose                                       |
| ----------------------------------------------------- | --------------------------------------------- |
| `DB_URL`                                              | PostgreSQL connection string                  |
| `BETTER_AUTH_SECRET`                                  | Better Auth secret (32+ characters)           |
| `BETTER_AUTH_URL`                                     | Public API base URL                           |
| `AUTH_TOKEN_PEPPER`                                   | HMAC pepper for setup codes and upload passes |
| `STORAGE_ACCESS_KEY_ID` / `STORAGE_SECRET_ACCESS_KEY` | S3 credentials                                |
| `MAIL_MODE`, `MAIL_FROM`                              | `mock` or `smtp` mail transport               |

## Commands

```bash
vp run check
vp run typecheck
vp run test
vp run build
```

Migrations are operator or CI steps only. The API never migrates on boot.

```bash
vp run --filter "@open-fms/database" generate
vp run --filter "@open-fms/database" migrate
```
