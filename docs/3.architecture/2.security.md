# Security

## Download rule

Only files with PostgreSQL status `clean` may be streamed to clients.

That decision is deliberate. Signed URLs cannot be revoked after a file leaves `clean`, so v1 proxies every download through the API and re-checks state on each request.

## Uploads

- Bytes are quarantined until scanning finishes
- SHA-256 is computed on stored bytes
- Type comes from magic bytes, not file extensions
- ZIP-like archives are checked for bomb patterns
- ClamAV `INSTREAM` can reject infected objects

## Credentials

- API keys are verified by Better Auth
- Setup codes and upload passes use HMAC-SHA256 with a versioned pepper
- Comparison uses constant-time verification
- Secrets are never logged

## Tenant isolation

Each authenticated request has one `caller_id`. Data access is filtered by that tenant. Admin routes are the only cross-tenant paths.

## Rate limits

Better Auth rate limiting is enabled with database storage so limits hold across API instances.

## What is not enabled in v1

- Presigned GET downloads
- Automatic status repair during reconcile
- Enabling an S3 backend before compatibility tests pass
