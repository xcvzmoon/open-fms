# Architecture

## System shape

```text
Clients ──HTTPS──► Nitro API (apps/api)
                      │
        ┌─────────────┼─────────────┐
        ▼             ▼             ▼
   PostgreSQL      S3 storage    Scan worker
   (metadata)   quarantine/clean  (SHA-256, type,
                                   archive, ClamAV)
```

PostgreSQL is authoritative for control state. Object storage holds bytes. Workers produce security verdicts. The API authenticates, authorizes, and orchestrates.

## Workspace layout

| Package                | Responsibility                                  |
| ---------------------- | ----------------------------------------------- |
| `apps/api`             | HTTP, auth, uploads, downloads, scheduled tasks |
| `packages/database`    | Drizzle schema, queries, migrations             |
| `packages/lifecycle`   | File state machine and quotas                   |
| `packages/storage`     | The only AWS SDK S3 adapter                     |
| `packages/scan-worker` | Claim, integrity checks, ClamAV, verdicts       |
| `packages/mailer`      | Auth email events                               |

## File lifecycle

```text
initiated → uploading → uploaded → quarantined → scanning
    → clean | infected | rejected | failed → deleted
```

Every transition matches `status` and `row_version` and updates exactly one row.

## Boundaries that must hold

1. Routes and workers never import `@aws-sdk/*`.
2. Nobody writes `files.status` except `@open-fms/lifecycle`.
3. Migrations never run on API boot.
4. Downloads re-check PostgreSQL state on every request. No presigned GET in v1.
5. Tokens and codes are stored as HMAC hashes only.

## Auth model

- Better Auth owns sessions, password hashing, API key verification, and rate limits.
- `caller_credentials` stores FMS policy (scopes, CIDR, size, rotation/revocation).
- `loadCallerContext` attaches tenant policy to requests.

## Storage and scan flow

1. Upload lands in quarantine
2. Worker claims a scan job
3. Checks run: SHA-256, type sniff, archive policy, ClamAV
4. Lifecycle promotes verified clean objects
5. Download API serves only `clean` files

## Scheduled tasks

| Task                   | Purpose                                       |
| ---------------------- | --------------------------------------------- |
| `sweep-expired`        | Expire codes, passes, sessions, stale uploads |
| `sweep-purge`          | Soft-delete files past `purge_after`          |
| `sweep-reconcile`      | Report DB vs storage mismatches               |
| `observability-canary` | Process and optional storage health           |
