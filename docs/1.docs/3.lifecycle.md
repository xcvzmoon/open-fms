# File lifecycle

The lifecycle module owns every status transition.

```text
initiated → uploading → uploaded → quarantined → scanning
    → clean | infected | rejected | failed → deleted
```

## Guarded transitions

Each transition:

1. Checks the expected `status`
2. Checks the expected `row_version`
3. Updates exactly one row

A zero-row update is a conflict (`FILE_ROW_VERSION_CONFLICT`), never success.

## Happy path

```text
createFileWithUploadSession
  → markUploading
  → completeAndEnqueueScan
  → markScanning
  → applyScanVerdict(clean)
```

`completeAndEnqueueScan` commits quarantine state, scan job, and quota conversion in one transaction.

## Verdicts

| Verdict | Meaning |
| --- | --- |
| `clean` | Promote object, allow download |
| `infected` | Keep quarantined or forensic |
| `rejected` | Structure or policy failure |
| `failed` | Worker or storage error |

A scan verdict never downloads anything by itself. Promotion verifies the sealed ETag before the database turns green.

## Quotas

| Counter | When it changes |
| --- | --- |
| `bytes_reserved` | Upload start |
| `bytes_used` | Upload complete |
| `file_count` | Upload complete |
| reserved release | Abort or expiry |
