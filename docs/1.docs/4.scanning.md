# Scanning

Workers turn quarantine objects into a security verdict.

## Pipeline

1. Claim a job with `FOR UPDATE SKIP LOCKED`
2. Read the sealed object
3. Verify SHA-256
4. Sniff MIME with `file-type`
5. Run structure and archive-bomb checks
6. Required ClamAV `INSTREAM`
7. Submit the verdict to the lifecycle module

## Why workers are separate

Hashing, archive inspection, and antivirus scanning are CPU heavy. Scan workers run as their own process so API latency stays predictable.

## Failure policy

| Condition            | Action                   |
| -------------------- | ------------------------ |
| Hash mismatch        | Fail job, do not clean   |
| Archive bomb         | Reject file              |
| ClamAV infected      | Mark infected            |
| ClamAV error         | Retry until max attempts |
| Storage copy failure | Leave file non-clean     |

Workers never write `files.status` themselves.

## Configuration

```bash
# required ClamAV
CLAMAV_HOST=127.0.0.1
CLAMAV_PORT=3310
```

Start the packaged consumer with `vp run --filter "@open-fms/scan-worker" start` after building. It requires `DB_URL`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`, and `CLAMAV_HOST`. SIGTERM cancels active work and closes resources. Expired running leases recover with a new fencing token.

ZIP inspection uses yauzl with bounded entry counts and declared and actual expansion limits. Stored and deflated entries are supported; encrypted, nested, malformed, or unsupported archives fail closed. See the scanner package README for limits.
