# Introduction

> Open FMS is a production file management API for S3-compatible object storage.

Callers upload and download over HTTP. They never need an S3 SDK, bucket names, or storage credentials. The service is byte-preserving and security-first: a file is downloadable only after PostgreSQL says it is `clean`.

## What is Open FMS?

Open FMS sits in front of RustFS, MinIO, or AWS S3. It owns authentication, quotas, malware scanning, promotion, retention, and audit history.

### Quarantine and scan

Every upload starts in quarantine. A scan worker claims jobs, verifies SHA-256, sniffs file type from magic bytes, checks archives for bomb patterns, and can run ClamAV. Only a verified clean object is promoted.

### Downloads with immediate revocation

Downloads are proxied through the API. Every request re-checks database state, so legal holds, deletes, and infected verdicts take effect immediately. Presigned GET is intentionally out of scope for v1.

### Lifecycle as the source of truth

Routes, workers, and sweepers call one lifecycle module. It owns the state machine, quota reserve/release, sealing, and promotion order.

### Storage without SDK leakage

A single AWS SDK v3 adapter handles S3 protocol details. Application code never imports `@aws-sdk/*`.

## Core packages

| Package | Role |
| --- | --- |
| `apps/api` | HTTP API, Better Auth, uploads, downloads, tasks |
| `@open-fms/database` | Drizzle schema and queries |
| `@open-fms/lifecycle` | File state machine and quotas |
| `@open-fms/storage` | S3 adapter |
| `@open-fms/scan-worker` | Integrity checks and verdicts |
| `@open-fms/mailer` | Auth email events |
